RAG: Local Document Question-Answering Assistant

A locally hosted, privacy-preserving document question-answering system combining an information-retrieval pipeline with local language model inference. Users upload Microsoft Word (.docx) documents, and the assistant segments, indexes, and retrieves the most relevant passages to synthesize answers strictly grounded in the uploaded context, preventing hallucinations and preserving complete data privacy without third-party API dependencies.

How the RAG Pipeline Works

The system operates in two distinct, coordinated stages:

  • Stage A: Document Ingestion & Indexing
    • Document Ingestion: Accepts .docx files up to 25 MB with validation against empty uploads.
    • Text Extraction: app/docx_parser.py extracts paragraphs and structured tables using python-docx, with an automated XML parsing fallback reading word/document.xml to guarantee complete data recovery.
    • Text Chunking: app/chunker.py segments the document into 600-character chunks with a 100-character sliding overlap, prioritizing paragraph breaks, then sentence boundaries, and finally word spaces to preserve context at boundaries.
    • Vector Representation: app/vector_store.py constructs a sparse TF-IDF representation combined with word bi-grams to capture multi-word terminology (e.g., “neural network”) alongside individual keywords.
  • Stage B: Question Answering & Grounding
    • Query Vectorization & Ranking: Natural-language questions are converted into matching TF-IDF vectors, and cosine similarity computes relevance against all indexed chunks.
    • Threshold Filtering: Configurable top-k chunks (default 4, selectable 1 to 8) are retrieved, filtering out any passages falling below the 0.01 similarity threshold.
    • Prompt Construction & Grounding: The RAG engine injects the retrieved context chunks into a constrained prompt directing the model to answer exclusively from the supplied text.
    • Hallucination Fallback: If no retrieved chunks satisfy the query threshold, the system returns a safe fallback: “I cannot find the answer in the uploaded document.”
    • Source Attribution: The UI renders the model's generated answer alongside exact retrieved source excerpts and similarity scores for full auditability.

Modular Implementation Architecture

  • app/config.py: Manages pipeline parameters, thresholds, and server ports.
  • app/docx_parser.py: Robust Word document parser with XML fallback.
  • app/chunker.py: Boundary-aware text chunking with sliding overlap.
  • app/vector_store.py: In-memory TF-IDF indexer with bi-grams and cosine ranking.
  • app/llm_client.py: Multi-backend local client for Ollama, LM Studio, and offline mode.
  • app/rag_engine.py: End-to-end retrieval orchestration and grounded prompt builder.
  • app/main.py: Asynchronous FastAPI server exposing REST API endpoints.
  • static/: Responsive browser interface featuring dark theme, upload zone, and source explorer.

Local LLM Integration & Privacy

The application supports three flexible operating modes:

  • Ollama Integration: Connects to local models (e.g., LLaMA 3, Mistral, Qwen) via http://127.0.0.1:11434.
  • LM Studio / vLLM Integration: Connects to OpenAI-compatible local inference endpoints via http://127.0.0.1:1234/v1.
  • Offline / Demo Mode: Performs grounded passage retrieval and extraction without running an external LLM server, ideal for lightweight testing.

Testing & Validation

  • 15 Automated Pytest Cases: Executed via python -m pytest tests/ -v.
  • Verified Modules: Document parsing with table extraction, chunk boundary integrity, TF-IDF scoring and bi-gram generation, grounding prompts, fallback triggers, and FastAPI REST endpoints.
