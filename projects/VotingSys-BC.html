Blockchain-Based Decentralized Voting System

A decentralized voting decentralized application (DApp) on Ethereum where an administrator manages candidate registration and voter eligibility, while authorized users securely cast votes via MetaMask. Unlike conventional voting systems that rely on a central database or administrator to store and count votes, this system enforces voting rules, eligibility checks, and real-time tallies directly on-chain using an immutable Solidity smart contract.

System Architecture

  • Frontend Layer (HTML5 · CSS3 · Vanilla JS): Responsive, dark-themed user interface displaying real-time election status, candidate profiles, and live results.
  • Web3 Connection & Provider (MetaMask + Ethers.js v6): Manages wallet connection, account switching, transaction signing, and JSON-RPC communication with the blockchain.
  • Smart Contract Layer (Voting.sol): Autonomous Solidity smart contract compiled and deployed to the EVM, executing access control, election lifecycle state transitions, vote validation, and tallying.
  • Local EVM Development Network (Hardhat): Local Ethereum network (Chain ID 31337) providing deterministic block generation, test accounts, and rapid deployment automation.

Election Lifecycle & State Machine

The core contract defines three strictly enforced stages:

  • Stage 0 — NotStarted: The administrator registers candidates (minimum of 2 required) and whitelists eligible voter wallet addresses. Voting transactions are blocked.
  • Stage 1 — Ongoing: The administrator starts the election. Candidate registration locks permanently, and whitelisted voters cast exactly one vote each.
  • Stage 2 — Ended: The administrator permanently closes the election. All further voting transactions are disabled while the final tally remains immutably readable.

Main Smart Contract Functions

  • addCandidate(name, description): Enables administrator to register candidates before voting starts.
  • registerVoter(address): Adds an eligible wallet to the voter whitelist and rejects duplicate registrations.
  • startElection(): Validates preconditions (e.g., minimum 2 candidates) and activates the voting stage.
  • endElection(): Permanently closes the election and locks the results.
  • vote(candidateId): Validates that the sender is whitelisted, the election is ongoing, and the wallet has not already voted before updating the candidate's tally.
  • getCandidates(), getVoterStatus(address), getResults(): Public read-only view functions retrieving contract state without gas fees.

On-Chain Double-Voting Prevention

Double voting is prevented directly inside the EVM smart contract logic rather than depending on client-side frontend checks. When an authorized voter submits a transaction, the contract verifies their prior voting flag. If the voter attempts to submit a second vote, the smart contract reverts the transaction immediately, preventing unauthorized or duplicate votes even if an attacker attempts to interact directly with the contract via raw JSON-RPC calls.

Testing & Validation
